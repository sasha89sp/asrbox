# ARCHITECTURE.md — Архитектура `asrbox`

Версия: `0.0.1` (каркас + рабочие модули `mod-dock`, `mod-widgets`, `mod-debug`, `mod-about` / `platform-api` / `platform-windows` / `app`).

## 1. Правило зависимостей (строго вниз)

- `crates/mod-*` и `crates/platform-windows` зависят **только** от `crates/core` и `crates/platform-api`.
- Прикладные модули не вызывают друг друга напрямую — только сообщения через `crates/core` и супервизор `crates/app`.
- Весь `unsafe` и прямые вызовы WinAPI (`windows = "0.61"`) изолированы исключительно в `crates/platform-windows`; в остальных крейтах действует `unsafe_code = "forbid"`.
- Во всём workspace действуют `unwrap_used = "deny"` и `expect_used = "deny"`.

## 2. Модель модулей, процессов и IPC

- **Единый контракт**: каждый модуль реализует трейт `Module` из `crates/core` (`start`, `stop`, `health`).
- **Управление в настройках**: каждый модуль имеет флаг `enabled` (выключенный не грузится, 0% CPU и 0 МБ RAM, `NF-007`) и `mode` (`inproc` или `process`).
- **Один исполняемый файл**: `asrbox.exe` работает как супервизор (трей + окно настроек). Дочерние модули запускаются этим же `.exe` с флагом `--module <имя>`.
- **Контроль версии**: супервизор и дочерний процесс сверяют `workspace.package.version`; дочерний процесс с несовпадающей версией не запускается (`NF-009`).
- **Политика перезапуска (`NF-006`, `NF-008`)**: при падении модуля супервизор перезапускает его с интервалами **1 сек, 5 сек, 30 сек**. После 3 падений подряд модуль отключается с уведомлением в трее и записью в лог.
- **IPC**: локальные именованные каналы Windows (**Named Pipes**), скрытые за транспортом в `core` / `platform-api`, чтобы в будущем заменить их на Unix-сокеты без правок прикладных модулей.

### Режимы исполнения модулей

| Модуль | Режим по умолчанию | Причина изоляции |
| --- | --- | --- |
| `mod-keyboard` | Отдельный процесс | Зависший хук не должен тормозить ввод системы (`NF-004`). |
| `mod-speech` | Отдельный процесс | После остановки Whisper оперативная память полностью освобождается (`NF-002`). |
| `mod-huawei` | Отдельный процесс | Сбой COM-порта / драйвера модема не роняет программу (`NF-006`). |
| `mod-webdav` | Отдельный процесс | Сетевые таймауты и долгие операции синхронизации не блокируют UI. |
| `mod-dock` | Один процесс на весь док | Неограниченное число независимых панелей (значки, разделители, кнопка настроек) без лишнего ОЗУ. |
| `mod-widgets` | Событийный UI + фоновый поток сети | Нулевой CPU в простое, настраиваемая прозрачность, мгновенный старт из кэша и неблокирующий WinHTTP. |
| `mod-debug` | Окно по открытию (`on-open`) | Живые логи, метрики процесса (RAM/CPU/GDI/USER) и помодульная нагрузка; 0% CPU при закрытом окне. |
| `mod-about` | Окно по открытию (`on-open`) | Версия, портативный режим, живые пути на диске и встроенный `CHANGELOG.md`; 0% CPU при закрытом окне. |
| `mod-screenshot` | Процесс по запросу | Живёт секунды на время захвата и затем завершается. |
| `mod-monitor` | Процесс при открытом окне | Не нагружает систему в фоне (`NF-001`, `NF-002`). |

## 3. Защита при работе и хранение данных

- **Портативный каталог**: все данные лежат в `./data/` рядом с `asrbox.exe` (`data/config/`, `data/logs/`, `data/cache/`, `data/backups/`, `data/models/`). Замена `asrbox.exe` в той же папке сохраняет все конфиги и кэши.
- **Один экземпляр**: именованный Windows mutex предотвращает запуск второй копии и активирует уже работающее окно.
- **Безопасный режим**: запуск с `--safe-mode` или зажатой клавишей `Shift` поднимает только системный трей без загрузки модулей.
- **Аварийное отключение клавиатуры**: жёстко заданная, не переназначаемая комбинация клавиш мгновенно останавливает `mod-keyboard`.
- **Кнопка `X`**: скрывает окно в системный трей; полный выход доступен только из меню трея.
- **Настройки и бэкапы**: перед миграцией схемы и перед применением конфигурации из WebDAV создаётся резервная копия; поля `settings_version` и `written_by` защищают настройки от перезаписи старой версией программы.
- **Секреты и Whisper**: пароли WebDAV и токены хранятся исключительно в Windows Credential Manager; секретные URL `.ics` и токены автоматически маскируются в логах `mod-debug`; модель Whisper скачивается лениво при первом включении с проверкой SHA-256.

## 4. Наблюдаемость и диагностика (`NF-010`)

- **Живая диагностика (`mod-debug`, пункт трея «Диагностика и логи...»)**:
  - кольцевой буфер последних 1500 записей по всем модулям (`app`, `dock`, `widgets`, `http`, `platform`, `debug`, `about`);
  - переключение подробных логов `TRACE` и записи в файл `data/logs/asrbox-debug.log` (ротация при 2 МБ) на лету без перезапуска;
  - фильтр по модулю, автоматическая редакция секретных ссылок/токенов;
  - живые метрики процесса (RAM МБ, % CPU, GDI/USER дескрипторы, uptime) и помодульная таблица нагрузки (события, перерисовки, ошибки, среднее/максимальное время кадра);
  - экспорт полного отчёта в буфер обмена («Копировать отчёт») и в файл `data/logs/diag-report.txt` («Сохранить отчёт»).
- **Онлайн-монитор (`mod-monitor`)**: зарезервирован для расширенного мониторинга дочерних процессов-модулей (`--module`).
