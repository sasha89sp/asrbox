# specs/mod-debug.md — Спецификация отладочного модуля (`mod-debug`)

Статус: согласовано, режим `on-open` (`0%` CPU при закрытом окне диагностики).
Связь с `SPEC.md`: `NF-001`, `NF-002`, `NF-007`, `NF-010`.

## Критерии приёмки (`DB-001..DB-007`)

- **DB-001 (Живой поток логов по всем модулям)**:
  Кольцевой буфер (до 1 500 записей) с временной меткой, уровнем (`ERROR` / `WARN` / `INFO` / `TRACE`), именем модуля (`app`, `dock`, `widgets`, `http`, `platform`, `debug`, `about`) и текстом события.
- **DB-002 (Включение/выключение полных логов на лету)**:
  Переключатель подробного режима (`TRACE`) без перезапуска программы и фильтр отображения по модулю.
- **DB-003 (Запись в файл с ротацией)**:
  Включаемая на лету запись логов в `./data/logs/asrbox-debug.log` с автоматической ротацией при достижении 2 МБ.
- **DB-004 (Метрики нагрузки процесса и модулей)**:
  Отображение RAM (Working Set), `% CPU`, числа GDI/USER-хэндлов, аптайма и таблицы по модулям (события, перерисовки, ошибки, среднее/максимальное время кадра в мс). Опрос ОС идёт **только** пока открыто окно диагностики.
- **DB-005 (Защита секретов в логах и отчётах)**:
  Автоматическая маскировка секретных сегментов URL календарей (`/private-.../`) и параметров `token=`/`key=`/`password=` до записи в буфер, файл и диагностический отчёт.
- **DB-006 (Экспорт диагностического отчёта)**:
  Кнопки «Копировать отчёт» (в буфер обмена) и «Сохранить отчёт» (`./data/logs/diag-report.txt` с открытием в `notepad.exe`) со сводкой версии, путей, метрик, очищенных конфигов и последних 300 строк лога.
- **DB-007 (Ограничения кода)**:
  В `crates/mod-debug` нет `unsafe`, нет `unwrap()`/`expect()`, нет прямых вызовов WinAPI.
