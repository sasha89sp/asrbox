# AGENTS.md

## Проект
Rust workspace (`asrbox`), portable `.exe` для Windows 10/11 (x64), сборка только на GitHub Actions.
Цель: модульная программа с минимальной нагрузкой на CPU/RAM (бюджеты в `SPEC.md`).

## Среда
Код пишется в Google AI Studio Build. ИИ не может компилировать и запускать Windows-код:
ничего не считается проверенным без лога GitHub Actions (`windows-latest`).

## Порядок чтения
1. `AGENTS.md`
2. `HANDOFF.yaml`
3. `SPEC.md` (раздел «0. Специфика проекта»)
4. `ATLAS.md`
5. `MAP.md` и `specs/<модуль>.md` только для модуля текущей задачи

## Формат вывода кода
- Только полные файлы (до 400 строк, функции до 60 строк) или точные патчи (путь, старый блок, новый блок).
- Запрещены заглушки (`todo!()`, `unimplemented!()`, «остальное без изменений», `...`).
- В начале ответа перечислить все затрагиваемые пути.
- Не удалять и не переименовывать файлы без явного разрешения.
- Не выдумывать API крейтов: если нет уверенности в сигнатуре/версии — прямо сказать об этом.

## Архитектура и запреты
- Каждый модуль реализует трейт `Module` (`start`, `stop`, `health`), работает в `inproc` и `process` режимах.
- Модули (`crates/mod-*`) зависят только от `crates/core` и `crates/platform-api` и не вызывают друг друга напрямую — только сообщения через `core`/супервизор.
- Не менять поведение без правки `SPEC.md` и подтверждения владельца.
- Не менять трейты `platform-api` и `Module` без подтверждения.
- Не добавлять зависимости без записи в `DECISIONS.md` (и обновления `docs/LICENSES.md`).
- Никакого `unsafe` вне `crates/platform-windows` (закреплено в `[workspace.lints.rust]`; каждый блок `unsafe` обязан содержать комментарий `// SAFETY: почему безопасно`).
- Никаких `unwrap()` / `expect()` в рабочем коде (закреплено в `[workspace.lints.clippy]`) — только `Result`.
- Никаких секретов в репозитории (пароли WebDAV и токены — только в Windows Credential Manager).
- Никаких разрушительных команд Git.

## Ресурсы и отладка
- События вместо опроса по таймеру; перерисовка только по событию.
- Ленивая загрузка тяжёлых модулей (`mod-speech` / Whisper, скачивание модели с проверкой SHA-256).
- Ключевые функции размечать для отладки/профилирования (`tracing::instrument`) с возможностью вкл/выкл на лету.
- Версия берётся только из `workspace.package.version` в корневом `Cargo.toml`.

## Лимиты кода и документов
- Файл кода — до 400 строк, функция — до 60 строк, крейт — до 15–20 тыс. строк.
- `ATLAS.md` — до 150 строк, `MAP.md` — до 100 строк, `HANDOFF.yaml` — до 80 строк.
- Закрытые баги переносятся в `docs/archive/bugs-closed.md`.

## Честность и закрытие
- Всегда разделять: «сделано», «проверено CI», «не проверено».
- В конце задачи обновить: `HANDOFF.yaml`, `MAP.md`, `ATLAS.md` (если нужно), `ARCHITECTURE.md`, `DECISIONS.md`, `BUGS.md`, `CHANGELOG.md`.
- Баги чинить строго по протоколу: фиксация -> лог -> локализация -> минимальная правка -> регрессионный тест -> CI -> закрытие. Две неудачи подряд — стоп и сбор диагностики.
