# SPEC.md — Спецификация `asrbox`

Версия спецификации: `0.0.1` (каркас проекта).

---

## Раздел 0. Специфика проекта

### 0.1. Назначение и позиционирование
`asrbox` — портативная модульная настольная утилита для Windows 10/11 (x64), объединяющая инструменты повседневной продуктивности, работы с речью, вводом, скриншотами, синхронизацией WebDAV, управлением устройствами Huawei и встроенной диагностикой производительности.

### 0.2. Целевая платформа и формат поставки
- **Операционная система**: Windows 10 (19041+) и Windows 11, архитектура **x86_64 (x64)**.
- **Портативность (Portable-first)**: приложение поставляется как единый исполняемый файл `asrbox.exe` без инсталлятора и без обязательных внешних DLL (допускаются только стандартные системные библиотеки Windows).
- **Каталог данных**: вся конфигурация, пользовательские профили, кеши, локальные базы и логи хранятся рядом с `asrbox.exe` в директории `./data/`. Запись в `%APPDATA%` и системный реестр по умолчанию запрещена (единственное допустимое исключение — явное включение автозапуска пользователем).
- **Среда разработки и проверки**: исходный код пишется в среде без локального Windows SDK; единственной средой компиляции, статического анализа, прогона тестов и сборки релизного бинарника является GitHub Actions (`windows-latest`).

### 0.3. Модульный состав workspace
| Слой | Крейт | Роль |

## Раздел 1. Нефункциональные требования и бюджеты (NF-001..NF-010)

| ID | Название | Бюджет / Целевой критерий | Способ проверки |
| --- | --- | --- | --- |
| **NF-001** | Портативность и изоляция данных | 100% конфигураций, кешей, состояний и логов хранятся в `./data/` относительно `asrbox.exe`. Нулевые неявные записи в `%APPDATA%` и реестр Windows при стандартном запуске. | Интеграционная проверка в чистом каталоге + аудит файловых путей в `core` и `platform-windows`. |
| **NF-002** | Время холодного старта | Время от запуска `asrbox.exe` до появления иконки в системном трее и готовности глобальных хоткеев — **<= 500 мс** на типовом ПК Windows 10/11 x64. | Замер времени инициализации встроенным профилировщиком при старте. |
| **NF-003** | Бюджет оперативной памяти в простое | Потребление RAM (Working Set) в свёрнутом состоянии в трее без активных тяжёлых речевых моделей — **<= 40 МБ**. | Наблюдение через `mod-monitor` и Windows Task Manager / Process Explorer. |
| **NF-004** | Бюджет CPU в простое | Средняя загрузка CPU в режиме ожидания — **<= 0.5%**. Запрещены busy-wait циклы; ожидание строится на event-driven механизмах ОС и таймерах с крупным шагом. | Замер через `mod-monitor` на интервале >= 5 минут простоя. |
| **NF-005** | Размер релизного артефакта | Размер `target/release/asrbox.exe` (x64, release) — **<= 15 МБ** без внешних несистемных DLL. | Проверка размера артефакта после `cargo build --release` в CI и `dumpbin /dependents`. |
| **NF-006** | Надёжность и безопасность памяти | 0 вызовов `unwrap()` / `expect()` во всём workspace; `unsafe` разрешён только в `crates/platform-windows` с обязательными комментариями `// SAFETY:`. Сбой одного модуля изолируется и не обрушивает хост-процесс молча. | `cargo clippy --workspace -- -D warnings`, `[workspace.lints]`, юнит-тесты отказоустойчивости. |
| **NF-007** | Управляемое логирование (вкл/выкл логов) | Глобальный переключатель логирования **вкл/выкл** на лету без перезапуска приложения. При выключенных логах файловая запись в `data/logs/` не производится (нулевые I/O-расходы). При включённых логах: ротация файлов, лимит суммарного объёма **<= 20 МБ**, фильтрация секретов (токены, пароли WebDAV/Huawei не попадают в лог). | Переключение флага логирования в рантайме, проверка отсутствия записи при выключенном состоянии и проверка ротации/маскирования секретов. |
| **NF-008** | Профилирование функций | Встроенный отключаемый профилировщик горячих функций и обработчиков событий (учёт числа вызовов, среднего времени, p95 и max-задержки в микросекундах). При выключенном профилировании накладные расходы **< 1%** (атомарная проверка флага). | Сравнительный бенчмарк вкл/выкл профилировщика и проверка отчёта метрик в `core` / `mod-monitor`. |
| **NF-009** | Онлайн-монитор нагрузки | Реальное отображение телеметрии приложения и системы в модуле `mod-monitor`: CPU % процесса и системы, RAM (Working Set / Private Bytes), количество потоков, активные модули, задержка цикла событий и таблица топ-функций профилировщика. Период обновления настраивается (по умолчанию **1000 мс**); когда окно монитора скрыто в трее, UI-обновление и избыточный опрос приостанавливаются. | Ручная и автоматическая проверка `mod-monitor` в открытом и свёрнутом режимах (подтверждение соблюдения NF-004 в трее). |
| **NF-010** | Сворачивание по кнопке `X` в трей и корректное завершение | Нажатие кнопки закрытия окна `X` (`WM_CLOSE`) **не завершает** процесс `asrbox.exe`, а скрывает окно в системный трей Windows с сохранением работы фоновых модулей и хоткеев. Полный выход выполняется только через пункт «Выход» контекстного меню трея или явную команду завершения с освобождением всех хэндлов, хуков и флаш-записью состояния за **<= 2000 мс**. | Проверка обработки `WM_CLOSE`, возврата окна кликом по иконке трея и полного завершения через меню трея. |
